IDENTITY INVENTORY
Asset Truth
“Inventory every account on every host — and the weaknesses each opens.”

The Problem

Service accounts, machine identities, reused local admins and default credentials are what attackers ride across an estate — and they never appear on a list sorted by CVE severity. Most teams can't say which accounts exist on which hosts.

What It Does

Identity Inventory builds an inventory of the accounts Tenable found on your hosts and classifies each as human, service / non-human (NHI) or machine. He flags privileged and non-expiring accounts, the same account on many hosts, SSH password logins and default credentials, ranks identities sitting on KEV, critical or crown-jewel hosts, and shows the hosts he can't see into because the scan had no credentials.

At a glance

Key Capabilities

  • Identities from the scan — local-user enumeration plugins (Linux user list, SMB local users and more) parsed into accounts, each with the hosts it lives on.
  • Classified — human, service / NHI or machine — from well-known Windows SIDs, AD machine accounts ($), Linux UID conventions and known service names.
  • Risk flags — privileged, non-expiring passwords, account reuse across five or more hosts, SSH password auth, default credentials, on a KEV, critical or crown-jewel host.
  • Honest about reuse — the same account name on many hosts is reported as account reuse — never claimed as a shared password.
  • Coverage — credentialed vs blind hosts by the Ensemble's single credentialed rule, and the scan credentials themselves.
  • Tags that route the work — Identity / NHI / Machine ID : <account> on its hosts, Identity Risk : Account Reuse, Identity Coverage : No Credentials, Owner : <name>; an AI model can propose more.
  • By tag — run over one tag's assets: the identities found on them, with host counts, privilege and host signals counted over the tag only, while each account keeps its estate-wide class and reach (account reuse ×N); tag writes stay inside the tag. Switch between the whole estate and your last 5 tags without re-running.

How It Works

Identity Inventory reads plugin output and identity plugins in your local navi.db; with Optimize his output search runs inside the database. The identity list pages and searches on the server. Tagging rebuilds the exact host list on the server from navi.db, behind the write gate and a confirm.

Who It's For

IAM and identity-security teams who need visibility beyond the directory, AD and Linux admins hunting reuse and default credentials, and threat teams tracing the accounts an attacker would use.
