EXPLORER › FIXED
Platform
“Prove what's actually fixed — and how long it took.”

The Problem

Remediation is only real when the finding closes. Showing what was fixed, when, how long it took and whether it met SLA usually means stitching exports together.

What It Does

Explorer › Fixed searches navi's remediation history: every fixed finding with each finding's first-seen and fixed dates, days to fix (computed, not trusted from navi's text field) and navi's own SLA Pass / Fail, SLA failures first.

At a glance

Key Capabilities

  • Remediation history — every fixed finding with plugin, name, severity and state.
  • Days to fix — computed from first seen to fixed.
  • SLA verdict — navi's own Pass / Fail, from navi's SLA calculation.
  • Worst first — SLA failures first, then by severity; the asset opens Asset Dossier.
  • Ask in plain English — a question becomes one read-only SQL query over the remediation-history table that you can edit before it runs (needs an AI model).
  • CSV and email — export the rows or send them through Notify & Reports.

How It Works

Explorer › Fixed reads the fixed table in your local navi.db (filled by navi config update fixed; navi's SLA calculation stamps each row Pass / Fail) and changes nothing.

Who It's For

VM leads proving progress, and auditors asking for remediation evidence.

Works Better With

SLA Tracker measures SLA across open and fixed findings; Explorer › Fixed is the row-level proof behind it.
