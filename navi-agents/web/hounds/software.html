SOFTWARE INVENTORY
Asset Truth
“Remember everything installed — and see which product carries the most risk.”

The Problem

Software inventory is fragmented: package data says one thing, CPE fingerprints another. Teams can't see version sprawl, can't spot end-of-life versions before they become unpatchable, and can't answer the board's simplest question: which product is dragging in the most risk?

What It Does

Software Inventory reconciles the software and CPE inventories into one product list, shows version sprawl, the most-deployed and the single-install products, checks versions against endoflife.date, flags the software that makes a host a crown jewel, and ranks a risk leaderboard by the KEV and critical exposure on the hosts that run each product.

At a glance

Key Capabilities

  • One product list, two sources — software and CPE inventories reconciled, each product badged with the source that saw it, and a delta view of what one source missed.
  • Sprawl, common, single-install — the product on fourteen versions, the package on half the estate, the one-off install nobody owns.
  • Lifecycle check — products matched to endoflife.date (on demand, cached) — assets on end-of-life or behind-latest versions.
  • Crown-jewel software — domain controllers, certificate authorities, databases, hypervisors, backup, security tooling, remote access — each role with a suggested ACR.
  • Risk leaderboard — products ranked by KEV, critical findings and VPR on their hosts and in their own plugins; full screen and email from the widget.
  • Ask in plain English — a question becomes one read-only SQL query over software, assets and findings that you review before it runs.
  • Software tags — Software : <product> (or a version, EOL set or crown role) — the server rebuilds the exact assets from navi.db.
  • By tag — run over one tag's assets: version sprawl, most-deployed and single-install software, lifecycle / EOL, crown jewels and the risk leaderboard are rebuilt for that tag, and tags written from that view reach only its assets. Switch between the whole estate and your last 5 tags without re-running.

How It Works

Software Inventory analyzes the software and cpes tables in your local navi.db on the server; the page gets counts and pages, never raw tables, so it works at hundreds of thousands of assets. The endoflife.date lookup runs from your browser. Tags go through navi behind the write gate and a confirm.

Who It's For

VM teams who want risk-ranked patching, IT asset managers reconciling inventories, and patch teams who want one worklist instead of three exports.
