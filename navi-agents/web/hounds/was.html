Arachne, the weaver Athena turned into the first spider — here she walks your web apps’ hidden surface: the dynamic findings a network scan never sees.

The Problem

Web Application Scanning findings live apart from the rest of vulnerability management. Which apps carry criticals, which OWASP categories dominate, which technologies keep showing up, and which apps haven't been scanned lately is hard to see across a whole program.

What It Does

Arachne turns navi's WAS data into two dashboards: an overview of every web app — findings by severity, the OWASP Top 10 summed across apps, the technology inventory, scan coverage and apps ranked by risk — and a per-app report. Every bar, category and chip opens the matching apps in Web App Dossier, and cohorts can be tagged on each app's Tenable asset.

At a glance

Key Capabilities

  • WAS overview — severity totals, OWASP Top 10 profile, technology inventory, crawl depth and recency, apps ranked by risk.
  • Per-app report — one app's severity, OWASP profile, tech stack and findings, with each plugin's raw stored output.
  • Click through to the apps — every metric, bar and chip opens Web App Dossier filtered to that group (a severity, an OWASP category, a technology, stale scans).
  • WAS tags — WAS OWASP : <category>, WAS Severity : <level> and WAS Technology : <tech> on each matching app's Tenable asset.

How It Works

Arachne reads the apps and findings tables in your local navi.db, filled by navi config update was (needs a Tenable WAS license); she parses navi's stored OWASP and tech lists for you. Tags go through navi behind the write gate and a confirm.

Who It's For

AppSec teams running a WAS program, and VM leads who want web-app exposure next to the rest of the estate.

Works Better With

Explorer › Web Apps finds an app, Web App Dossier maps one app's surface, and Arachne gives the program view. Exposure Score counts web-app exposure in each asset's score, and Automation re-applies the WAS tags on its schedule.
