Carl Linnaeus, the father of taxonomy who gave every living thing its name and rank — here he classifies every asset by what it is.

The Problem

You can't own, scope or prioritize an asset you can't name. In most estates a large share of assets carry no class at all, so they fall out of ownership, scan policy and reporting — and nobody can say whether they are servers, printers or PLCs.

What It Does

Linnaeus classifies every asset from the tags the Ensemble has written, and shows exactly what is still unclassified. From operating-system fingerprints and device signals he suggests classes for the untagged assets, groups them into cohorts you can approve, and writes the tags.

At a glance

Key Capabilities

  • Classes from tags — the Ensemble's own taxonomy — Asset Inventory, IoT, Device Type, OS — rolled up into Windows, Linux, macOS, Unix, Server, Workstation, Mobile, IoT, OT, Medical, network, hypervisor, cloud, Web Application, Mainframe and Unclassified — IoT Squad vendor tags (Ubiquiti, pfSense, Hikvision …) included.
  • Standard device types — PC, PC-VDI, VDI, Server-on-prem, Server-VDI, Printer, Camera, Switch, Router, Firewall, Wireless Access Point, Load Balancer, Network Device — offered as you tag, and each maps to its class.
  • OS and device signals — untagged assets grouped by Nessus's own device type (printer, camera, switch, firewall …) or by detected OS ("Windows Server 2022 — 40 assets"), each cohort one approval away from a tag.
  • OS explorer — OS families and versions for the untagged assets, with a confidence rating for each fingerprint.
  • Tag by OS in plain English — "tag all my assets by OS with a confidence over 70" becomes a plan you review before anything is written.
  • Environment Explorer — a zoomable sunburst of class → subnet → software and Docker, down to each asset (which opens in Asset Dossier).
  • Risk and ownership per class — KEV and critical findings, cloud assets, and classified assets with no owner — so the unclassified bucket becomes a ranked worklist.
  • By tag — run over one tag's assets: every class count, coverage %, OS signals cohort and Explorer view covers just that tag, each asset keeps its whole-estate class, and classification tags written from that view touch only its assets. Switch between the whole estate and your last 5 tags without re-running.

How It Works

Linnaeus reads tags, OS fields, OS-identification and Nessus Device Type plugin output, and device signals from your local navi.db. An asset counts as cloud only when navi holds a real AWS, Azure or GCP id for it — navi stores a missing one as a blank, which is not cloud. Class lists page on the server. Tags use the scheme Asset Inventory : <facet>: <value> (Class, OS, Device Type, App), written behind the write gate and a confirm.
