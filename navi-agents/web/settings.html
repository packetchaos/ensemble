⬇ External downloads

Some specialists enrich navi.db with a public, read-only data source from outside Tenable. By default each one stops at a Human approval — external download card before fetching. Auto-approve downloads skips that card: pressing ▶ Run downloads straight away and the page shows a one-line “Auto-approved download: <url> (Settings)” note instead. Nothing runs on page open, tag writes stay gated, and offline every source still falls back to its bundled snapshot. Without approval the server uses the snapshot only — no network.

🧪 Test run

Try the Ensemble without touching your real tag taxonomy. While Test run is on, every tag category a specialist creates gets your prefix phrase and a - — the value is never changed, and a category that already carries the prefix is left as is. Everything that reads tags back (What the Ensemble know, Done so far, Owner / SLA dispositions, Exposure Score…) recognises both the plain and the prefixed name. Clean up afterwards in Tag Removal (its test-run tags filter). Removals and ACR on a category you type are always exact.

🧹 Rebuild navi.db

navi's asset sync only adds and updates — an asset that ages out of the pull window or falls off licensing is never deleted from navi.db. Specialists can keep tagging those stale assets, and because the next sync never brings them back, navi can't see (or remove) their tags. A rebuild drops the chosen tables, re-creates them and pulls N days fresh — navi config update full -rebuild --days 90. Local navi.db only; nothing in Tenable changes.

⚡ Optimize navi.db for the Ensemble

Adds the Ensemble's indexes to navi.db (vulns by plugin and by asset; tags, compliance, certs and software by asset_uuid), builds two small summary tables (hx_plugin, hx_asset: one row per plugin and per asset) that the specialists read instead of the findings, runs a bounded ANALYZE and marks the vulns indexes unordered so GROUP BY asset_uuid never turns into hours of random reads — navi's own ⚙ Optimize indexes (navi config optimize) doesn't index asset_uuid. It holds navi.db's write lock while building (≈ 1–1.7 h at 420M vulns), won't start while a navi job runs, and a re-run only refreshes the statistics (seconds).

👑 Crown jewels

One definition for every page: an asset whose Asset Criticality Rating (ACR) is at or above this line is a crown jewel — CISA KEV, End of Life, Certificates, Attack Paths, Exposure Score, Ownership, SLA, Scan Health, the dashboards and the Ensemble Report all count the same assets. ACR comes from Tenable; set it per business tier in Criticality Calibration.

Default 8. Changing it rebuilds every cached result — re-run a specialist to see its new numbers.

⏱ SLA policy

Per-severity remediation windows (days) that drive SLA Tracker — SLA Adherence. Save runs navi config sla reset (a local navi.db config write — not gated). Then Build Fixed and Recalculate SLA to stamp Pass/Fail verdicts — both stream in the CLI window below.
